This page is written for the person who has to approve GraphMind for use on developer machines.
Every claim on it names the file in the repository that makes it true, so it can be checked rather
than believed. The short policy version is
[`SECURITY.md`](https://github.com/Hegazy360/GraphMind/blob/master/SECURITY.md); vulnerability
reports go there.

## One paragraph

GraphMind is a **local-only** developer tool. `npx graphmind-ai` starts a server bound to
`127.0.0.1:4747` that serves a viewer and accepts execution events from an instrumented agent over a
local WebSocket. It records those events in a SQLite database under `~/.graphmind` and can hold the
agent at a gate (before an LLM step, before/after a tool call, on error) until the developer — or a
coding agent the developer allowed, through `graphmind resume` — resumes it. From 0.6.0 a resume can
run a held tool call with **edited arguments**, which is why control carries a credential. There is no cloud component, no account, and no data path off the machine other than a
four-field CLI telemetry record that is off with one environment variable. The whole product is MIT
licensed and built in the open.

## Threat model

Full text with the CVE-2025-49596 mapping: [SECURITY.md → Localhost threat
model](https://github.com/Hegazy360/GraphMind/blob/master/SECURITY.md#localhost-threat-model).
Summary:

| Boundary | Position | Evidence |
| --- | --- | --- |
| Network | The server binds `127.0.0.1` only, no other interface, ever. | `packages/cli/src/server.ts` — `const host = '127.0.0.1'` |
| Browser | A web page in your browser cannot talk to it: WebSocket upgrades and HTTP requests need a loopback `Host` (defeats DNS rebinding) and either no `Origin` or the served viewer's own. Everything else is `403`. Every response forbids framing (`frame-ancestors 'none'`, `X-Frame-Options: DENY`), sends `Referrer-Policy: no-referrer` and `nosniff`, `/api` adds `no-store`, and no response carries a CORS header. The resume endpoint is POST + `application/json` + Bearer only; no GET mutates. | `packages/cli/src/origin-guard.ts`, `control-http.ts`; `packages/cli/test/origin-guard*.test.ts`, `control-http.test.ts`; `security/tests/control-http-exposure.test.ts` |
| Control | Input edits, injected results, breakpoints, step mode and every non-GET `/api` route need a per-start 128-bit token: the **viewer** token (delivered only in the `#token=` URL fragment via a 0600 redirect file) or the **agent** token (`~/.graphmind/run/serve-<port>.json`, 0600), which `serve --allow-control=off\|resume\|inject\|edit` limits in the server (default `off`). Constant-time comparison; no `?token=`, no cookies; `serve --json` never prints a token. `--no-edit-input` refuses all edits. The stored `exec.resumed` records `principal` from the credential. | `packages/cli/src/control-auth.ts`, `run-files.ts`, `pause-registry.ts`; `security/tests/control-auth.test.ts`, `control-registry-isolation.test.ts` |
| Command execution | The server never spawns a process in response to network input. But an authorized input edit chooses the **arguments** of a tool call the app is holding — a `shell` tool then runs what the editor chose, as your app — and an injected LLM completion can name the next tool call and its arguments. Hence the credential and level above, for both. The MCP proxy has no listening socket. | `packages/cli/src/hub.ts`, `server.ts` (no `spawn`); `packages/cli/src/mcp-proxy/proxy.ts` (no `listen`) |
| Local peers | **Any local process, as any OS user, can read runs over loopback** (the read API needs no credential, although the database file is 0600), and a **tokenless** viewer socket can still continue, retry and abort a held run (0.5 behaviour, deprecated) — whatever `--allow-control` says. It cannot edit inputs, inject results or change breakpoints or step mode, and a peer cannot take over another's live run or pause (flooding fresh run ids does not evict the claim of a run still in flight, whether its app is connected or reconnecting, and does not reopen a finished or abandoned run). | `security/tests/run-isolation.test.ts`, `control-auth.test.ts`, `control-registry-isolation.test.ts`; `internal/decisions.md` "runs are claimed, not squatted" |
| Host application | Instrumentation is fail-open: detached = synchronous no-op; a debugger that disconnects releases every gate; adapters never throw into the host. | `packages/client/src`; `examples/soak` (fail-open checks in CI) |
| Untrusted input | Envelopes are zod-validated at ingest; oversized payloads are truncated type-preservingly; the JSON-RPC boundary of the MCP proxy is fuzzed. | `security/tests/ingest-fuzz.test.ts`, `protocol-fuzz.test.ts`, `mcp-proxy-fuzz.test.ts`, `mcp-boundary-fuzz.test.ts` |

<Aside type="caution" title="Out of scope, and said plainly">
Exposing the port through a tunnel, a reverse proxy or a `0.0.0.0` bind puts an unauthenticated
service on a network. GraphMind will not do that for you and reports that depend on it are not
vulnerabilities. Stored runs are **not encrypted at rest**; disk encryption is your control.
</Aside>

## Architecture, in words

1. **Your agent process** links an adapter (`@graphmind-ai/sdk`, `@graphmind-ai/anthropic`,
   `@graphmind-ai/openai`, `@graphmind-ai/langgraph`, `@graphmind-ai/mcp`; `graphmind-ai` on PyPI;
   the `graphmind` gem). Every adapter is a thin layer over one runtime, `@graphmind-ai/client`,
   which opens **one outbound WebSocket to `ws://127.0.0.1:4747/ingest`** (override:
   `GRAPHMIND_URL`). If nothing answers within 300 ms the session is detached and every call is a
   no-op.
2. **The server** (`graphmind-ai`, the CLI) receives versioned JSON envelopes
   (`{gm, seq, ts, runId, type, payload}`), validates them against
   `@graphmind-ai/schema`, stores them, and fans them out to viewers on `ws://127.0.0.1:4747/ws/ui`.
   Gate holds are decided in the *client*: the server referees `exec.resume` (first writer wins per
   pause, credential and level checks, no placeholder or truncated values) and relays it to the
   connection that owns the run. Coding agents release pauses with `graphmind resume`, an HTTP
   client of the same server bounded by `--allow-control`; `graphmind mcp` stays read-only.
3. **The viewer** is a static bundle served by the same process (`packages/cli/viewer-dist`). It
   makes no requests to anything but its own origin.
4. **`graphmind mcp-proxy -- <command>`** is a stdio man-in-the-middle for MCP servers. It spawns the
   command *you* name, relays JSON-RPC both ways, and reports to the local hub as an ordinary ingest
   client. It opens no port.

Outbound connections made by GraphMind code, exhaustively: the loopback WebSocket above; the CLI
telemetry `POST` (below); `graphmind demo --live` and `graphmind init` fetch nothing. The docs and
website are separate static deployments.

## What is stored where

## Every kill switch

Read by the **instrumented application** (TypeScript, Python and Ruby SDKs implement the same
table — `packages/client/src/env.ts`, `python/graphmind/env.py`, `ruby/lib/graphmind/env.rb` —
except where a row says otherwise):

| Switch | Effect |
| --- | --- |
| `GRAPHMIND_DISABLED=1` | Instrumentation off. Beats everything, including an explicit `enabled: true` in code. No socket, no buffering, wrappers are identity functions, `gm.run` still runs your function. |
| `NODE_ENV=production` | Off by default in production; `GRAPHMIND=1` re-enables. Python/Ruby read the documented list of environment-name variables the same way. |
| `pauseTimeoutMs` (session option) | Cap on how long any gate may hold; default is "hold until resumed", which is only possible while a debugger is attached. |
| `GRAPHMIND_HIDE_INPUTS` / `GRAPHMIND_HIDE_OUTPUTS` / `GRAPHMIND_HIDE_TOOL_ARGS` / `GRAPHMIND_HIDE_TOOL_RESULTS` = `1` **(0.5.0; since 0.6.0 any value but `0`/`false`/`off`/`no` counts, so a misspelling hides rather than records)** | Whole-field redaction at the emit point, by node kind: the named field is replaced with the string `"__REDACTED__"` before it leaves the process, affected events carry `redaction: {count, keys}`, the viewer shows a "hidden by …" chip, and `inject` refuses to send the placeholder back. Coarse by design — a reviewer can reason about it. |
| `GRAPHMIND_ON_LOOP=off` / `GRAPHMIND_LOOP_THRESHOLD=0` / `GRAPHMIND_LOOP_ALLOW=<tools>` **(0.5.0)** | Disable the identical-tool-call loop hold, or exempt named tools from it (it only ever holds while a debugger is attached). |
| `GRAPHMIND_DISABLE_EDIT_INPUT` **(0.6.0; any value but `0`/`false`/`off`/`no`)** | This app never takes an edited input: it does not announce `edit-input`, and every edit is refused before any of your code sees it — the code path that lets a remote request choose a held tool call's arguments is off. TypeScript and Python; the Ruby SDK never offers edits. |
| `GRAPHMIND_BREAK_ON_ERROR_RESULT=0` / `GRAPHMIND_BREAK_ON_TRUNCATED=0` **(0.6.0; on by default, only `0`/`false`/`off`/`no` turn one off)** | Turn off a [smart hold](/reference/environment/#smart-holds): an error-shaped tool result, or an LLM step cut off in the middle of a tool call. They are not breakpoints, so `serve --pause-on-error off` does not affect them. TypeScript adapters and `graphmind mcp-proxy` (the proxy reads its own environment). |

Read by the **CLI / server**:

| Switch | Effect |
| --- | --- |
| `DO_NOT_TRACK=1` (any value but unset, empty, `0`, `false`, `off` or `no`) | Telemetry off. Wins over every GraphMind-specific setting. |
| `GRAPHMIND_TELEMETRY=0` (or `false`) | Telemetry off. |
| `GRAPHMIND_TELEMETRY=log` | Telemetry payload printed to stderr with a `[graphmind telemetry]` prefix, **nothing sent** — the audit mode. Also prints under `CI`. |
| `CI` set | Telemetry off. |
| `--pause-on-error off` / `GRAPHMIND_PAUSE_ON_ERROR=off` | Start with no breakpoint at all (the default arms pause-on-error; it can also be narrowed to one node kind). |
| `GRAPHMIND_ALLOWED_ORIGINS` | The *opposite* of a kill switch: it widens which browser origins may connect. Unset by default; `*` disables the check and is for setups you fully control. |
| `serve --allow-control off` (the default) | The agent token (`graphmind resume`) can do nothing: not release, inject or edit a pause, change breakpoints, or start the demo. `resume` / `inject` / `edit` widen it step by step. |
| `serve --no-edit-input` **(0.6.0)** | Refuse every input edit from every credential; apps are not told the server supports edits. |
| `GRAPHMIND_RETENTION=off` | Never prune stored runs. |
| `graphmind record --no-redact-secrets` **(0.5.0)** | Opt out of the default secret-key redaction in exports (`authorization`, `cookie`, `api_key`, `password`, `token`, … matched as a whole key or as parts split on `_`, `-` or camelCase, so `max_tokens` is never touched). |

Precedence tables with tests: [Environment variables](/reference/environment/) and
[Telemetry](/reference/telemetry/); telemetry is pinned by `packages/cli/test/telemetry.test.ts`.

## Telemetry, exactly

One `POST https://graphmind.ai/api/telemetry` per CLI command with
`{event, installId, version, ts}` — command name, random UUID, package version, time. Never
arguments, prompts, run data, hostnames or user names. Fire-and-forget, 3 s timeout, socket
`unref()`ed so it can never hold the process open. Adapters send nothing. Disclosure:
`packages/cli/TELEMETRY.md`. The security suite scans captured telemetry bodies for canary secrets
and asserts the key set is exactly those four (`security/tests/adapter-leaks.test.ts`).

## Versioning and deprecation

Full policy: [Stability & versioning](/reference/stability/).

- **Semantic versioning**, one version number across every package and language. While the major
  is `0`, a **minor** is the only release that may change behaviour incompatibly and says so in
  the CHANGELOG; a **patch** never does.
- **Wire protocol** compatibility is governed separately by the envelope's `gm` field (the
  protocol major, currently `1`) and negotiated in the `hello` / `hello.ack` handshake
  (`versions.protocol`). Payloads are *loose* objects: unknown fields are preserved, unknown event
  types are stored and shown rather than dropped, so a newer SDK against an older server (or the
  reverse) degrades rather than breaks. A `gm` bump is a major event and will not happen in a
  patch.
- **Deprecations** are announced in a minor, in the CHANGELOG and with a **runtime warning**
  printed once, and the deprecated thing is removed in the next major, not before. Nothing is
  deprecated today.
- **Support window**: the latest minor receives security fixes as patches; the previous minor
  for 90 days after the next minor ships (`SECURITY.md`).

## Questions your security team will ask

**Does any of our data leave the machine?** No. Run data travels only over loopback and is stored
under `~/.graphmind`. The one outbound request is the four-field telemetry record described above,
off with `DO_NOT_TRACK=1`.

**Can a website reach the local server?** No. `Origin`/`Host` enforcement on every request and
upgrade; tested including DNS rebinding, `Origin: null`, other local ports, and a browser-originated
attempt to resume a held gate. The HTTP resume endpoint is POST + JSON + Bearer with no CORS
headers, and the viewer cannot be framed.

**Can our coding agent drive it?** Through `graphmind resume`, only as far as you started the
server with: `graphmind serve --allow-control=off|resume|inject|edit` (default `off`), enforced in
the server, not in the CLI. The viewer shows the level and marks every pause a coding agent
released ("resumed by agent"). `graphmind mcp` has no control tools. One gap, while tokenless
viewer sockets are deprecated rather than removed: an agent with a shell can open one and
**continue, retry or abort** a held call at any level (never inject, edit, or change
breakpoints — those need a token).

**Does it execute anything?** The server never spawns a process from network input. The MCP proxy
spawns exactly the command you pass it, and nothing else.

**Can it break our production application?** It is off by default under `NODE_ENV=production` and
unconditionally off with `GRAPHMIND_DISABLED=1`. When on but detached it is a synchronous no-op.
When attached, a debugger disconnect releases every gate. Adapters never throw into the host.

**What is the blast radius of the stored data?** One SQLite file, owner-only permissions, on the
developer's disk, unencrypted. Treat it like a local log of prompts. Retention prunes it; deleting
it deletes everything.

**Can we redact prompts / tool arguments?** From 0.5.0: `GRAPHMIND_HIDE_INPUTS`,
`GRAPHMIND_HIDE_OUTPUTS`, `GRAPHMIND_HIDE_TOOL_ARGS`, `GRAPHMIND_HIDE_TOOL_RESULTS` replace whole
fields with `"__REDACTED__"` before they leave the process. Exports redact values under a documented
list of secret-looking keys by default. Two limits to know before you rely on them: the **tool-only** switches hide the
tool node's own input and output, but in an agent loop the same values also pass through the model —
its `tool_use` blocks and the next request's `tool_result` messages — so to keep tool data out of the
recording entirely, set `GRAPHMIND_HIDE_INPUTS` and `GRAPHMIND_HIDE_OUTPUTS`. And error messages are
never redacted (they can echo data). Exports match *keys*, not values: a secret typed into a prompt is
exported as recorded. In `graphmind mcp-proxy`, `HIDE_TOOL_RESULTS` also stops a failed result being
quoted into its error, and `HIDE_INPUTS` also removes the server's command-line arguments from the run
label and metadata. The TypeScript, Python and Ruby SDKs implement the same switches with identical wire
output, held to shared conformance fixtures and a differential test generated from the TypeScript client.

**How do we verify what we install is what you built?** `npm view <pkg>@<v> dist.attestations` and
`npm audit signatures` for npm; PEP 740 attestations on PyPI; SBOM and `SHA256SUMS` on the GitHub
Release; every action in the build pinned by SHA; CodeQL and Scorecard public.

**Who is accountable?** A single maintainer (`CODEOWNERS`). Report privately via GitHub Private
Vulnerability Reporting or `hello@graphmind.ai`; acknowledgement within 3 business days, fix
targets by severity in `SECURITY.md`.

**What are the known gaps?** No encryption at rest; any local process — under any OS user — can
read runs over loopback, and a tokenless viewer socket can still continue, retry or abort a held
call (deprecated; never inject, edit or change breakpoints); releases up to 0.4.4 are not provenance-attested; the Ruby gem is not yet on
RubyGems; Scorecard items that need repository settings are open.
