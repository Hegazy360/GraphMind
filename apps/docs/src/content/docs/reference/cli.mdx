The `graphmind-ai` package installs the `graphmind` binary: the local server, SQLite storage,
the keyless demo, the trace importer, the MCP proxy, the MCP server, and the bundled viewer UI.

<Tabs syncKey="pkg">
<TabItem label="npx">

```sh
npx graphmind-ai            # serve
npx graphmind-ai demo       # keyless demo
```

</TabItem>
<TabItem label="global">

```sh
npm i -g graphmind-ai
graphmind
```

</TabItem>

**Requires Node ≥ 22.13.** SQLite is built into Node, so there are no native dependencies.

<Aside type="caution" title="Local only">
The server binds `127.0.0.1`. Reading runs needs no credential: any process on this machine —
any OS user, a container on the host network — can read what is recorded over loopback. Since
0.6.0, **controlling** a paused agent carries a credential for input edits and every non-GET
API route (see [control credentials](#control-credentials)). It is a devtool, not a service —
never expose the port.
</Aside>

## `graphmind serve` (default)

Start the local server and open the viewer. Running `graphmind` with no command does this.

```sh
graphmind                          # port 4747, open the browser
graphmind --port 4848              # different port (always binds 127.0.0.1)
graphmind --db ./x.db              # database file (default ~/.graphmind/graphmind.db)
graphmind --no-open                # do not open a browser
graphmind --pause-on-error tool    # arm the default error breakpoint on tools only
graphmind --pause-on-error off     # start with no breakpoints at all
graphmind --allow-control=resume   # let `graphmind resume` (a coding agent) continue/retry/abort, and set breakpoints / step mode
graphmind --no-edit-input          # refuse every input edit, from anyone
graphmind serve --json --no-open   # headless: one JSON line on stdout, never a token
```

`serve --json` prints exactly one line to stdout, `{"port":4747,"url":"http://127.0.0.1:4747","pid":12345,"version":"0.6.0"}`,
and sends everything else (the server log) to stderr. It never prints a token.

### Control credentials

At start the server mints two random 128-bit tokens. They change on every start.

| Token | Who holds it | How it travels | What it may do |
| --- | --- | --- | --- |
| **viewer** | The browser the CLI opens | Only in the URL fragment `#token=…`. The CLI opens the browser through a private redirect file (`$GRAPHMIND_HOME/run/open-<port>.html`, mode 0600), not through a URL on a command line, and prints the `#token=` URL only when stdout is a terminal. The viewer removes the fragment from the address bar at once (`history.replaceState`) and keeps the token in `localStorage` for this origin. | Everything: continue, retry, inject, abort, edit inputs, breakpoints, step |
| **agent** | `graphmind pauses / wait / resume` | Written to `$GRAPHMIND_HOME/run/serve-<port>.json` (default `~/.graphmind/run/`, directory 0700, file 0600) as `{port, pid, url, agentToken, version}`; removed on a clean exit. | Limited by `--allow-control` (below). Default **off**: nothing. |

`--allow-control` levels for the agent token: `off` (default) · `resume` (continue, retry,
abort, breakpoints, step mode, starting the demo) · `inject` (adds injecting a result) · `edit`
(adds running a held call with edited arguments). The level is enforced by the server, so a
coding agent allowed to run `graphmind resume` cannot make it do more than you started the server
with — though with a shell it can still continue, retry or abort over a tokenless viewer socket
(below). `--no-edit-input`
refuses every input edit from any credential and drops `edit-input` from the capabilities the
server announces to apps.

On the wire: the browser presents the viewer token as the WebSocket subprotocol
`gm.auth.<token>` next to `graphmind.v1` (the server selects `graphmind.v1`); HTTP clients send
`Authorization: Bearer <token>`. Tokens are compared in constant time (SHA-256 digests).
`?token=` query parameters and cookies are never read. A presented token the server does not
know is refused (401), never downgraded.

What needs a credential: any `exec.resume` that carries an edited `input` or injects a result;
`breakpoint.set` / `breakpoint.clear` / `mode.set`; every non-GET `/api` route (including `POST
/api/demo/start`); every CLI control command. A viewer socket **without** a token keeps the part
of the 0.5 behaviour that chooses nothing — continue, retry and abort — and can never edit an
input, inject a result, or change breakpoints or step mode (the server answers `error {code:
'forbidden'}`, followed by the real `state`; the viewer does not offer inject or edit there, and
disables its run/step switch, breakpoint controls and palette actions, saying why). That
tokenless mode is **deprecated**: the server logs a one-time note when one connects, and it will
need the token in a later minor (see [Stability](/reference/stability/#deprecated-in-060)).

Every response carries `Content-Security-Policy: frame-ancestors 'none'`, `X-Frame-Options:
DENY`, `Referrer-Policy: no-referrer` and `X-Content-Type-Options: nosniff`; `/api` responses add
`Cache-Control: no-store`. No response ever carries a CORS header.

### Who is allowed to connect

Binding loopback is not on its own enough, because two browser mechanisms reach a loopback
server from a page you merely visited: a **WebSocket handshake is exempt from the same-origin
policy**, and **DNS rebinding** makes an attacker's domain same-origin for a plain `fetch`.
Since 0.3.0 every HTTP request and every upgrade is checked:

| Client | Result |
| --- | --- |
| No `Origin` header — the SDK, `curl`, the CLI itself, tests | **Allowed.** A web page cannot omit it. |
| A loopback origin on this server's own port — the viewer it serves | **Allowed** |
| Any other origin | **403** |
| A `Host` header that is not a loopback name | **403** (closes DNS rebinding) |

A forwarded port (SSH `-L`, VS Code, a devcontainer) passes the `Host` check whatever port it
uses. The `Origin` check is stricter: the browser's origin must use the **same port number** as
the server, or be listed in `GRAPHMIND_ALLOWED_ORIGINS`. With a mismatched port the viewer
loads a blank page, because its own scripts are refused. See
[remote development](/guides/remote-development/).

`GRAPHMIND_ALLOWED_ORIGINS` opens it explicitly — a comma-separated list, or `*` to disable the
check entirely. You need it for exactly one ordinary case, a viewer running on its own dev
server:

```sh
GRAPHMIND_ALLOWED_ORIGINS=http://localhost:5199,http://127.0.0.1:5199 graphmind
```

## `graphmind demo`

The keyless first-run experience. Replays a bundled recording of a trip-planner agent with a
planted bug: `convertCurrency` inverts an exchange rate, and the budget check throws on the
absurd total.

The replay goes through the real ingest pipeline and honours the real control protocol — the
planted error genuinely pauses, and `inject` / `continue` / `retry` / `abort` steer the replay
onto the matching pre-recorded branch. It uses a server already running on the target port, or
starts one in-process and keeps it up until <kbd>Ctrl</kbd>+<kbd>C</kbd>.

```sh
graphmind demo               # replay the recording (no API key)
graphmind demo --live        # run the real demo agent with your API key
graphmind demo --port 4848   # target a specific server port
```

`--live` needs a GraphMind monorepo checkout (or `GRAPHMIND_DEMO_AGENT_DIR` pointing at the demo
agent) plus `ANTHROPIC_API_KEY` or `OPENAI_API_KEY`.

## `graphmind init [dir]`

Look at a project, work out which agent framework it uses, and print the exact install command
plus a copy-pasteable snippet that instruments it.

```sh
graphmind init              # detect and print the steps
graphmind init --install    # also run the package-manager install
graphmind init --write      # write a graphmind.example.ts snippet file
```

Detection is deliberately dumb and transparent: it reads the manifest, matches dependency names,
and reports what it found. In `package.json` it recognises `ai` (or `@ai-sdk/anthropic`, `@ai-sdk/openai`, `@ai-sdk/react`),
`@anthropic-ai/sdk`, `openai`, `@modelcontextprotocol/sdk` (1.x) and
`@modelcontextprotocol/server` (2.x, with a `serveStdio` snippet), and `@langchain/langgraph`,
`@langchain/core` or `langchain`. In `pyproject.toml`, `requirements.txt`, `Pipfile` or
`setup.cfg` it recognises `openai`, `anthropic`, `langgraph`, `langchain`, `langchain-core` and
`crewai`. It does not read a `Gemfile`: for Ruby, follow [Ruby](/integrations/ruby/). For an MCP
server it also offers `graphmind mcp-proxy`, which needs no adapter. There are no prompts (so it
is safe in CI and from coding agents) and nothing is written unless you pass `--write`.

## `graphmind import <trace-file>`

Convert an exported trace file into a run, stored with `source: "import"` and rendered with the
viewer's "imported" treatment — history only, no live features. Best-effort; prints a summary
(nodes, errors, duration, skipped spans) and a viewer deep link.

```sh
graphmind import trace.json
graphmind import trace.json --db ./x.db
```

Accepted inputs: **OTLP/JSON** (OTel collector `file` exporter, SDK JSON exporters) and **flat
span lists** (OpenInference / Arize Phoenix-style JSON or JSONL). Recognised span dialects:
Vercel AI SDK OTel spans, OTel GenAI semantic conventions, and OpenInference. Unrecognised spans
are imported as generic nodes or skipped with a note.

## `graphmind mcp-proxy -- <command>`

Debug **your** MCP server. Spawns `<command>` as a child, speaks stdio JSON-RPC to your MCP host
on one side and to the server on the other, relays every frame verbatim, and reports the
conversation to GraphMind as a live run you can hold and steer. Any language, no code changes.

```sh
graphmind mcp-proxy -- node my-server.js
graphmind mcp-proxy -- python -m my_server
graphmind mcp-proxy --trace -- ./target/debug/my-server
```

Point a host at it by moving the existing command inside the proxy:

```sh
claude mcp add my-server-debug -- npx -y graphmind-ai mcp-proxy -- node my-server.js
```

| Flag | Meaning |
| --- | --- |
| `--trace` | One line per frame on stderr — works with no GraphMind running |
| `--wait-for-attach` | Hold the first frame until the debugger attaches (≤3s), so `initialize` can be gated |
| `--inherit-stderr` | Give the server the real stderr fd; its log then does not appear on the session node |
| `--max-frame-bytes <n>` | Frame-assembly ceiling (default 64 MiB); above it the relay becomes a raw byte pipe |
| `--port <n>` | GraphMind port to report to |

Run it with no command and it prints a working recipe. Nothing is ever written to stdout except
the protocol. The proxy speaks up on stderr in three situations:

| What happened | stderr | Exit | On the graph |
| --- | --- | --- | --- |
| The command cannot be started (`ENOENT`; on Windows a `.cmd`/`.bat` target, `EINVAL`) | `cannot run "<cmd>": <reason> — <hint>` | `127` | `SpawnError` on the session node; the run ends `error` |
| The server exits before its first JSON-RPC frame | The exit reason and the last 40 lines of its stderr | the server's | `McpServerExitedEarly` with the last 200 lines / 32 KB of stderr; the run ends `error` |
| The server writes a non-JSON-RPC line to stdout | One line quoting up to 200 bytes, plus a count at the end of the session | — | A red **stdout noise** node under **protocol** (the first 25 lines) |

The environment variables `GRAPHMIND_HIDE_*`, `GRAPHMIND_LOOP_THRESHOLD`, `GRAPHMIND_ON_LOOP` and
`GRAPHMIND_LOOP_ALLOW` apply to the proxy too; see [environment](/reference/environment/).
Full detail: [MCP proxy](/integrations/mcp-proxy/) and
[debugging MCP servers](/debugging/mcp-servers/).

## `graphmind mcp`

The other direction: serve **your recorded runs** to MCP clients (Claude Code, Cursor, …) over
stdio. It has no control tools — releasing a pause from a coding agent goes through
`graphmind resume`, bounded by `serve --allow-control`. Read-only tools:
`list_runs`, `get_run`, `get_node`, `find_errors` — each result carries a deep link into the
viewer. Reads the SQLite database directly, so it works while the server and viewer are closed.

```sh
claude mcp add graphmind -- npx graphmind-ai mcp
```

`--db` selects the database; `--port` sets the port used in generated deep links (default 4747 —
pass it if you run `graphmind` on a different port). Full detail: [MCP tools](/reference/mcp/).

## `graphmind pauses`

List the pauses held right now on the server at `--port`.

```sh
graphmind pauses                 # table: run, pause, node, point, reason, state, since
graphmind pauses --run <id>      # one run
graphmind pauses --json          # {"pauses":[{runId, pauseId, nodeId, point, reason, smart?, loop?, editable?, since, state, app?}]}
```

`state` is `open`, or `resolving` while a resume is being answered. Reading needs no token.

## `graphmind wait`

Block until a pause is open, then print it and exit — the building block for a coding agent's
debug loop.

```sh
graphmind wait                           # any run, up to 90 s (the default)
graphmind wait --run <id> --timeout 60   # one run; --timeout 0 waits forever
graphmind wait --json                    # one JSON line
```

The summary names the run, pause, node, gate point, reason (breakpoint, error, loop, smart
hold) and whether the pause is `editable`, shows the held call's recorded input (and error, if
any), and lists the `graphmind resume` commands that apply — ids shell-quoted, `--port` named
when it is not 4747; none when an id carries a control character. Text an app wrote (ids, names,
a hold's detail) is printed with control and bidi characters shown as `\uXXXX`, never raw. Polls
are at least 1 s apart even against a server that does not long-poll. Values over 2 KB are written to a
private temp file (mode 0600) and only the path is printed (`inputFile` / `outputFile` /
`errorFile` in `--json`).

## `graphmind resume`

Release a pause. Reads the agent token from `$GRAPHMIND_HOME/run/serve-<port>.json`; what it may
do is set by `serve --allow-control`.

```sh
graphmind resume <pauseId> --run <id> --action continue
graphmind resume <pauseId> --run <id> --action retry
graphmind resume <pauseId> --run <id> --action inject --output '{"rows":[]}'
graphmind resume <pauseId> --run <id> --action continue --input @fixed-args.json   # needs --allow-control=edit
graphmind resume <pauseId> --run <id> --action abort --operator "claude code" --json
```

`--output` / `--input` take JSON or `@file`. `--input` replaces the named top-level argument keys
of **this call only**; the tool really runs with them. `--operator` is a display-only label
(sanitized, at most 64 characters) shown next to "resumed by agent". `--timeout <s>` sets how
long to wait for the app's answer (default 30, at most 120). The first resume for a pause wins
— from the viewer, another agent or this command — and any other gets `taken`.

### Exit codes (`pauses`, `wait`, `resume`)

| Code | Meaning |
| --- | --- |
| 0 | ok (resumed; a pause was found; listed) |
| 1 | usage error, or something unexpected |
| 2 | timeout (`wait`: no pause in time; `resume`: no answer from the app yet, or an earlier resume of that pause is still unanswered — `still-resolving`; run it again) |
| 3 | no GraphMind server on that port — none at all, or one older than 0.6 (no control plane; the message names its version) |
| 4 | nothing to act on (no such pause; `wait --run`: the run ended) |
| 5 | not authorized (stale or unreadable token file, `--allow-control` too low, `--no-edit-input`) |
| 6 | refused (the app would not run the edit; the app or pause cannot take an edit — `not-editable`; or the value holds a placeholder / truncated preview) — the call is still held |
| 7 | taken (another resume won the pause) |

## `graphmind skill`

Print the GraphMind [Agent Skill](https://docs.claude.com/en/docs/claude-code/skills) — setup
for each framework, running the server headless, and the pause/wait/resume loop — or install it
for Claude Code in the current project.

```sh
graphmind skill                     # print SKILL.md
graphmind skill --install           # write .claude/skills/graphmind/SKILL.md here
graphmind skill --install --force   # overwrite an existing one
```

The file ships in the npm package (`skills/graphmind/SKILL.md`).

## `graphmind runs`

List what is stored, and keep it from growing forever.

```sh
graphmind runs                      # list recent runs
graphmind runs --keep 50            # show the 50 newest
graphmind runs --prune              # apply the retention policy now
graphmind runs --prune --keep 50    # ...keeping only the 50 newest
graphmind runs --prune --days 7     # ...and only the last 7 days
graphmind runs --rm <runId>         # delete one run
graphmind runs --clear --yes        # delete every run
```

Default retention is **200 runs / 30 days**. `--clear` refuses to act without `--yes`.

## `graphmind record <runId>`

Export a persisted run — as NDJSON (one wire envelope per line, the same shape `graphmind demo`
replays and `WS /ingest` accepts), or as one self-contained HTML page.

```sh
graphmind record run_01H8…                        # → graphmind-run-<runId>.ndjson
graphmind record run_01H8… --out bug-4471.ndjson
graphmind record run_01H8… --html                 # → graphmind-run-<runId>.html
graphmind record run_01H8… --html --out bug-4471.html
```

`--html` inlines the viewer's own JS and CSS and embeds the run's envelopes in the page, so the
file opens in any browser with **no server and no network** — the same UI you were just looking
at, reading a frozen run. It needs the built viewer, which the published package ships (from a
monorepo checkout, run `pnpm build:viewer` first). Live-looking debugger controls are hidden in
an export, because there is nothing to control.

Lists recent run ids when the given one is not found. See
[exporting a run](/debugging/recording-runs/).

### Secret-looking keys are redacted by default

Both formats replace the value under any secret-looking key with `"__REDACTED__"`, and say how
many they replaced:

```text
$ graphmind record run_db4bd5541228 --out a.ndjson
recorded 4 events of run run_db4bd5541228 → …/a.ndjson
redacted 4 values under 4 distinct keys (--no-redact-secrets keeps them)

"input":{"user":"alice","password":"__REDACTED__","api_key":"__REDACTED__","max_tokens":42,"accessToken":"__REDACTED__"}
```

| Flag | Effect |
| --- | --- |
| `--redact-secrets` | The default. |
| `--no-redact-secrets` | Keep every value as recorded; prints `secrets NOT redacted (--no-redact-secrets): the file holds every value as recorded`. If both flags are given, the last one wins. |

The keys: `authorization`, `cookie`, `set-cookie`, `api_key`, `apikey`, `password`, `passwd`,
`secret`, `client_secret`, `private_key`, `access_token`, `refresh_token`, `token`, `bearer`.
A key matches in any case, either whole or as a run of its parts split on `_`, `-` or a
camelCase boundary:

| Matches | Does not match |
| --- | --- |
| `Authorization`, `x-api-key`, `http_authorization`, `accessToken`, `X-Refresh-Token`, `PassWord` | `max_tokens`, `maxTokens`, `tokenizer`, `apiKeys`, `secrets` |

Over-matching is deliberate: `token_count` and `client_secret_expires_at` are redacted because
one of their parts is a listed key. Keys are matched at any depth, arrays included. The
loop-hold fingerprint (`exec.paused.loop.fingerprint`) is also replaced, because it is a digest
of the whole input.

<Aside type="caution" title="An export still carries your payloads">
Redaction looks at **keys, never values**. A secret typed into a prompt, a `Bearer …` string
inside a message, a token in a URL, or a secret repeated in an error message is exported as
recorded. Read the file before attaching it to a public issue. To keep values out of the
recording in the first place, use the [`GRAPHMIND_HIDE_*` switches](/reference/environment/#recording-less).
</Aside>

## HTTP & WebSocket endpoints

| Endpoint | Purpose |
| --- | --- |
| `WS /ingest` | Instrumented apps. Schema envelopes; `hello` → `hello.ack` handshake (the ack carries current breakpoints + mode). |
| `WS /ws/ui` | Viewers. UI subprotocol (below). |
| `GET /health` | `{ ok, name, version }` |
| `GET /api/runs` | `{ runs: RunInfo[] }`, most recent first |
| `GET /api/runs/:id/events` | Paginated events (`?afterSeq=&limit=`) |
| `GET /api/session` | Who a Bearer token is: `{principal, agentLevel, editInput, hubCapabilities, version}` (401 for an unknown token) |
| `GET /api/pauses[?runId=][&wait=<s>]` | Open pauses; `wait` long-polls until one opens (or the run ends), at most 120 s |
| `GET /api/runs/:runId/pauses/:pauseId` | One pause with the held node's recorded input (and error) |
| `POST /api/runs/:runId/pauses/:pauseId/resume` | Release a pause (below). Bearer + `application/json` only |
| `POST /api/demo/start` | Replay the bundled demo (Bearer since 0.6) |
| `GET /*` | The built viewer (a placeholder page when the bundle is absent) |

### `GET /api/runs`

Each run: `{ id, app, startedAt, finishedAt, status, schemaVersion, source, eventCount,
errorCount, live }`. `status` is `running | ok | error | aborted`; `source` is
`live | import | demo`; `live` is whether the owning app socket is currently connected.
Timestamps are epoch milliseconds; `finishedAt` is `null` while running.

### `GET /api/runs/:id/events?afterSeq=N&limit=M`

Returns `{ runId, total, events, nextAfterSeq }`. `events` are full wire envelopes in ascending
`seq` order with `seq > afterSeq` (default: from the start). `limit` defaults to 1000 (max
5000). `nextAfterSeq` is the cursor for the next page, or `null` on the last one. Unknown run:
404 `{ error }`.

### `POST /api/runs/:runId/pauses/:pauseId/resume`

Body: `{action, output?, input?, requestId?, operator?, timeoutMs?}`. Requires
`Authorization: Bearer <token>` (401 otherwise) and `Content-Type: application/json` (415
otherwise: a form cannot send it). `GET`, `PUT`, `DELETE` and `OPTIONS` on the path answer 405;
no response carries CORS headers. The request waits for the app's answer — `timeoutMs`,
default 30 000, at most 120 000 — and at most 16 long-polls (this and `GET /api/pauses?wait=`)
run at once (429 beyond); long-polls without a valid credential may hold at most 8 of them, so
tokenless readers can never crowd out a resume (`graphmind wait` sends the agent token when it
can read it). Answer:

```json
{ "outcome": "resumed", "runId": "…", "pauseId": "p3", "requestId": "…", "principal": "agent" }
```

| `outcome` | HTTP | Meaning |
| --- | --- | --- |
| `resumed` | 200 | The app released the gate (`exec.resumed`). |
| `refused` | 422 / 403 | 422: the app refused the edit (`code`: `schema`, `shape`, `placeholder`, `truncated`, `disabled`, `unsupported`), the server refused a placeholder/truncated value, or the app or pause cannot take an edit (`not-editable`: an app without `edit-input`, a pause that is not `editable`) — the gate is **still held**. 403: `forbidden` (level too low) or `edit-refused` (no edit rights, `--no-edit-input`). |
| `taken` | 409 | Another resume is being answered (`pause-taken`), or the app released the gate for another resume, or on its own, instead of this one (`superseded`). A resume the app answers late is still answered by what the app did: `resumed` if it ran. |
| `timeout` | 202 | No answer in time (`no-answer`); an earlier resume of this pause is still unanswered and nobody is waiting on it (`still-resolving` — it reopens within 5 s if the app never answers); or the app disconnected (`app-disconnected`, whether the socket was already closing or closed a moment later) — a detached app releases its gates on its own. |
| `no-such-pause` | 404 | The server knows the pause is closed, the run finished, or no app owns the run. |

A pause the server never saw (its `exec.paused` was refused or not tracked) is forwarded
best-effort rather than refused.

### UI subprotocol (`WS /ws/ui`)

JSON text frames, each an object with a `type` discriminant. Wire envelopes are never sent bare
— they ride inside `event` / `control` messages. Types are exported from the package
(`UiClientMessage`, `UiServerMessage`, `RunInfo`, `WireEnvelope`).

**Server → viewer**

| Message | When |
| --- | --- |
| `{ type: 'welcome', versions, breakpoints, mode, control? }` | Immediately on connect. `control` (0.6): `{principal, agentLevel, editInput, hubCapabilities}` — `principal` is `viewer`, `agent` or `anonymous` |
| `{ type: 'state', breakpoints, mode }` | Whenever debug state changes (from any viewer) |
| `{ type: 'runs', runs }` | Reply to `subscribe` `'*'` |
| `{ type: 'run.update', run }` | Pushed to `'*'` subscribers on run lifecycle changes |
| `{ type: 'replay.start', runId, count }` | Reply to `subscribe` of a run |
| `{ type: 'event', runId, envelope }` | One envelope — replayed history first, then live tail |
| `{ type: 'replay.end', runId }` | History done; everything after is live |
| `{ type: 'error', message, runId?, code?, pauseId?, outcome?, requestId? }` | Bad request / refused control. `code` (0.6): `pause-taken`, `no-such-pause`, `no-owner`, `edit-refused`, `not-editable`, `forbidden`, `placeholder`, `truncated`, `still-resolving`, `app-disconnected`. On an `exec.resume` the server did not forward, `outcome` (`refused`, `taken`, `timeout` or `no-such-pause`) and your own `requestId`, echoed when you gave one |
| `{ type: 'resume.result', runId, pauseId, requestId, outcome, code?, message? }` | 0.6: the app's answer to an `exec.resume` this socket sent (outcomes as in the HTTP table) |

**Viewer → server**

| Message | Meaning |
| --- | --- |
| `{ type: 'subscribe', runId }` | A run id → replay-then-tail; `'*'` → run-list snapshot + updates |
| `{ type: 'unsubscribe', runId }` | Stop that subscription |
| `{ type: 'control', envelope }` | A full control envelope: `exec.resume` (routed to the app socket owning `envelope.runId`), or `breakpoint.set` / `breakpoint.clear` / `mode.set` (update server state, relay to all apps, broadcast `state`; 0.6: needs the viewer token or the agent token at `resume`) |

Replayed envelopes keep their original `seq`; dedupe on `(runId, seq)`. Control envelopes can be
built with `createEnvelope` from `@graphmind-ai/schema` with any `seq` — the server re-mints
sequence numbers when relaying to apps.

Since 0.6 the server keeps a **pause registry** (keyed by run and pause id, fed only by frames
that passed the run claim) and referees `exec.resume`: the first resume for an open pause is
forwarded with a `requestId` (the server mints one if you gave none) and the pause becomes
`resolving`; any other gets `error {code: 'pause-taken'}`. An `exec.refused` from the app, or no
answer within 5 s, reopens it. A pause the server knows is closed gets `no-such-pause`. The
stored `exec.resumed` carries `principal` — who won, from the credential — and the resumer's
sanitized `operator` label; an app cannot set either. The server refuses an `exec.resume` whose
edited `input`, or whose `inject` output, still contains `"__REDACTED__"`, a
`__graphmindTruncated` marker or the truncation suffix (`code: placeholder / truncated`), and
does not relay it. Only `pauseId`, `action`, `requestId`, `output` (with `inject`) and `input`
are relayed.

## Storage

`node:sqlite` (built into Node ≥ 22.13, zero native deps), WAL mode, at
`~/.graphmind/graphmind.db` (override: `GRAPHMIND_DB` or `--db`). Events are keyed
`(run_id, seq)` with `INSERT OR IGNORE`, so replay dedup falls out of the protocol. A single
payload larger than 512 KB is stored as a marker so one enormous event cannot bloat the database
or wedge the viewer. Every size ceiling and timeout is on [limits](/reference/limits/).
